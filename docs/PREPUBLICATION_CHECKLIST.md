# Publication checklist

- [x] Keep original project and source media read-only; work in a separate candidate.
- [x] Separate historical private counts from the three-item newly authored demo.
- [x] Label implemented workflow, experimental recognition and future plans.
- [x] State substantial AI assistance and later maintenance changes.
- [x] Keep media, frames, personal review/progress, model weights and caches outside the publication allowlist.
- [x] Use relative runtime manifests and generic input configuration.
- [x] Exercise approval, revocation and failed-save paths with synthetic fixtures.
- [x] Include dependency groups and reproducible demo commands.
- [ ] Owner approves repository name, final file allowlist and publication scope.
- [ ] Owner selects a project-wide license, or explicitly publishes with no project license for now.
- [ ] Re-run final allowlist/hash/content checks immediately before upload.
- [ ] Verify actual remote URL, commit and file readback after upload.
- [ ] Update the fixed local publication-progress file only with genuine remote evidence.
- [ ] Add a hosted demo or formal recognition benchmark only if actually produced.

Screenshots included in the candidate use generated self-authored cards. Runtime speech, audio/video, crops, personal study records and optional model outputs remain excluded. Any future third-party teaching/film material needs separate redistribution permission.
